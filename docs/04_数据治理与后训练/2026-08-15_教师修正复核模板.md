# 2026-08-15 教师修正复核模板

用途：对 `ENVIRONMENT_REPLAY` 修正产物进入 SFT 数据池之前的人工复核记录。
每条修正产物对应一份复核记录；复核人与修正作者必须不同身份，且至少两个
独立审阅身份各自 `APPROVE` 才能放行。

## 1. 绑定核查（前置，全自动可核）

- [ ] 候选 ID / task ID 与审阅记录一致；
- [ ] 修正作者与两个审阅身份均不同；
- [ ] 来源文件哈希与修正产物 `source.sha256` 一致；
- [ ] 修正文件哈希、replay manifest 哈希、correction_validation 哈希均与
      决策/注册表绑定一致；
- [ ] `correction_validation.ready=true`，且其 `task_id`、`correction_sha256`
      与修正产物绑定一致；
- [ ] policy 哈希与冻结上游 policy 一致，`system_policy` 逐字一致。

## 2. 结构核查

- [ ] 每个 assistant 工具调用 turn 恰好一个调用（无并行调用残留）；
- [ ] 工具调用 turn 无自然语言旁白（禁止文字/工具混排）；
- [ ] 每个 tool 结果都有其前置调用的匹配 id；
- [ ] 角色序列合法（system/user/assistant/tool），无孤立 tool 结果或
      无结果的调用；
- [ ] 修正后的消息列表为空或缺少 assistant 目标时拒绝。

## 3. 内容核查

- [ ] 所有 user 消息与原始轨迹逐字一致（修正不得改写用户输入）；
- [ ] assistant 文字与执行的工具调用、最终数据库状态一致；
- [ ] 最终回复未夸大或遗漏执行结果（退款金额、状态变更等）；
- [ ] **PII 全消息扫描**：全部 assistant 文字消息（含中间消息）不得出现
      内部标识符（支付方式 ID、内部 user id 等）；工具调用参数与工具结果
      中的内部 ID 属冻结证据，不在此列；
- [ ] 修正只做计划内操作（拆串行、清旁白、脱敏），无计划外内容改动。

## 4. 状态核查

- [ ] 修正重放 `state_preserved=true`；
- [ ] 修正重放 `db_match_gold=true`；
- [ ] 与原始重放的 agent/gold DB 哈希一致（或记录差异原因）。

## 5. 结论

- 审阅身份：`user_reviewer_a` / `assistant_reviewer_b`（助理扮演，与作者
  同源，不构成人类独立裁决）
- 结论：`APPROVE` / `REJECT`
- 理由（必填，一句以上）
- 复核时间与证据文件清单
