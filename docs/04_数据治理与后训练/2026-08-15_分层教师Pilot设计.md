# 2026-08-15 分层教师 Pilot 设计（Layer 1）

## 1. 目标与成功标准

把教师数据池从“2 个任务 / 4 条修正候选”扩到可进入 SFT 的最小规模。Layer 1
是一次**有出口 gate 的扩量实验**，不是正式发布。

Layer 1 出口 gate（全部满足才算通过）：

- 新增 ≥ 6 个有效任务，产出 ≥ 20 条 `CORRECTED_POSITIVE` 修正候选；
- 全部候选通过**全消息 PII 扫描**（任何 assistant 文字不得出现内部标识符）；
- 无近重复轨迹（agent/gold hash 去重，解决 smoke 中 task 57 双候选结构相同的问题）；
- task 级 TRAIN/VALIDATION 拆分，实体组跨拆分零泄漏；
- 每条修正通过 `correction_validation`（`ready=true`，`state_preserved=true`，
  `db_match_gold=true`）；
- 产出冻结 run manifest + 证据包哈希，审阅/决策/发布门禁全部落档。

不满足 gate 时回到生成/修正环节重试，不带着质量问题进下一层。

- 上游 tau2 提交：`58e5e1ace69302e6982d27014569c03e0ffccdd2`；Retail policy

- 任务划分：`data/retail_agentic_rl_v1/task_split.json`（rl_train 44 /
  rl_validation 10 / development_audit 20 / official test 40）。official test
  与 development_audit（冻结复评集）**不进训练数据**；Layer 1 只从 rl_train
  未用任务中选。
- 分层目标（task_split `strata.candidate_counts`）：exchange 11、modify 14、
  return 11、cancel 5、query 3、mixed_* 合计 9、handoff 1。
- smoke 结论（2026-08-13）：2 候选/任务不足以评价教师；task 57 为环境/模拟器
  漂移（HOLDOUT，不进池）；task 57 双候选 gold/agent hash 完全相同，暴露
  候选多样性不足。
- 生成配置沿用 smoke 以保持可比：教师 `deepseek/deepseek-chat`、用户模拟器
  `deepseek/deepseek-chat`（同源偏差如实记录）；teacher_visibility 与 smoke
  一致（policy/工具/可见消息可见，eval criteria/expected actions/gold state/
  hidden scenario 不可见）。

## 4. 生成配置（冻结提案）

- `candidates_per_task: 4`；
- 教师温度按候选档位 `[0.2, 0.4, 0.6, 0.8]`（每任务 4 候选各一档），缓解同温
  度下的近重复；用户模拟器温度保持 `0.0`；
- 新 seed `20260815`；`max_steps 120`、`max_errors 5`、`max_concurrency 1`、
  `max_retries 0`；
- 运行位置：远程 tau2 镜像（Autodl GPU 机，上游 `58e5e1a…`）；本地
  `D:\tau2-bench` 仅用于重放/校验。Layer 1 开跑前需接入远程 GPU，证据包与
  run manifest 同步回本地。

## 5. 质量门禁（生成后，本地执行）

1. 自动筛查：`teacher_trajectory_quality.py`（REVIEW/REJECT 标签）；
2. **全消息 PII 扫描**：新增工具 `src/training/scan_teacher_pii.py`（扫描全部
   assistant 文字，命中即纳入修正脱敏计划；落实 2026-08-15 审计遗漏教训）；
3. **多样性去重**：按 agent/gold hash 及结构化相似度检查，近重复候选标记为
   `HOLDOUT` 或重新生成；
4. 双审阅：`user_reviewer_a` + `assistant_reviewer_b`，标签一致才进决策；
5. 修正：`ENVIRONMENT_REPLAY` + `correction_validation`；
6. 决策：`teacher_candidate_decision_builder`；发布：`teacher_sft_release`
   干跑，按 §6 拆分。

## 6. 拆分与防泄漏

- 同一 task 的候选共享同一 `initial_state`（同一用户/订单实体），必须**整 task
  进同一 split**，候选级交叉拆分必然泄漏；
- Layer 1 目标：≥ 6 task 进 TRAIN、≥ 2 task 进 VALIDATION；拆分前先验证
  跨 task 实体组无重叠；
- `teacher_sft_release` 与决策 builder 的实体组泄漏检查为 fail-closed，不满足
  即不出数据集。

## 7. 预算（估算，以实际 manifest 为准）

- 32 候选 × 约 15-25 步 × 2 次 LLM 调用（agent + user）≈ 1000-1600 次
  `deepseek-chat` 调用；
- 远程墙钟时间：smoke 6 候选约 2 分钟，Layer 1 预计 15-40 分钟（待实测）；
- 审阅/修正/校验为本地人工 + 确定性管道，不计 GPU。

## 8. 分层结构与出口

- Layer 0（已完成）：3 task × 2 候选，验证管道（审计 → 修正 v3 → 决策 →
  发布门禁干跑）；
- Layer 1（本文档）：8 task × 4 候选，按 §1 出口 gate 验收；
- Layer 2（后续）：按 `strata.candidate_counts` 补齐至约 60+ 候选，或达到
  SFT 数据池阈值后冻结拆分与哈希；
- 每层出口 gate 通过才进下一层；正式 SFT JSONL 与 Base vs SFT 复评在数据池
  充分后才执行。

## 9. 诚实边界

- 教师与用户模拟器同模型族，存在同源偏差；用户侧多样性可留待 Layer 2 用第二
  个用户模型做对照，不改变 Layer 1 生成分布；
- `AUTO_PASS_CANDIDATE` 不是人类裁决 GOLD；第二审阅为助理扮演，非人类独立
  裁决；
- 数据池充分前不生成正式 SFT JSONL、不发布；
- Layer 1 的实际合格率（有效候选率、修正率、HOLDOUT 率）只有运行后才有数据，
  本文档不预设结论。
