# 用户模拟器 Fail-Fast 设计与实现

> 日期：2026-08-13  
> 适用范围：隔离的 Retail Agentic RL 工程路线  
> 目标：外部用户模拟器故障不得伪装成 Agent 失败或进入 reward、SFT、DPO、GRPO 数据。

## 1. 问题来源

Qwen3-4B Tool-SFT 多轮诊断第一次启动时，DeepSeek 返回 API Key 无效。上游用户模拟器调用链仍产生了“转人工”等回退文本，没有在本项目边界立即终止。如果只检查是否生成轨迹文件，可能把外部服务故障误当成正常用户行为。

必须区分：

```text
Agent failure：模型选错工具、参数错误、遗漏步骤或违反政策
System failure：用户模拟器认证、配额、网络、服务端或响应结构异常
```

前者是评测和后训练对象，后者是无效实验数据。

## 2. 两层 Fail-Fast

### 2.1 运行前 API 健康检查

正式 `run()` 在加载本地 GPU 模型前，对配置的用户模拟器模型执行一次 `max_tokens=1` 的最小请求。它检查：

- Key 是否有效；
- 模型是否有访问权限；
- 账户是否因余额或配额无法请求；
- 服务端是否返回合法 choices。

成功后写入 `user_simulator_preflight.json`，不保存请求文本、响应文本或 Key。`environment-only-preflight` 和 `--preflight-only` 仍保持零外部 API 调用；只有正式运行才执行该检查。

### 2.2 运行中异常包装

每次 `respond_to_user()` 调用动态用户模拟器时，经过 `generate_with_fail_fast()`：

- 401/403、无效 Key：不重试，立即中止整次运行；
- 余额或配额耗尽：不重试，立即中止；
- 429、5xx、网络超时：最多 3 次，按 1 秒、2 秒退避；
- 空响应：标记 `INVALID_RESPONSE`，立即中止；
- 其他未知异常：标记 `UPSTREAM_REQUEST_FAILED`，立即中止。

所有不可恢复故障写入独立的 `system_failures.jsonl`，不写入 `raw_rollouts.jsonl`，不计算 reward。

## 3. 失败产物语义

运行级 `failure_manifest.json` 对用户模拟器故障显式记录：

```json
{
  "failure_domain": "SYSTEM",
  "failure_stage": "USER_SIMULATOR",
  "training_eligible": false,
  "reward_eligible": false,
  "abort_run": true
}
```

错误消息和 traceback 在持久化前会移除 `sk-...` 与常见 API Key 赋值形式。任何 secret 仍不得写入配置、日志说明或 Git。

第一版选择“终止整次运行”，而不是悄悄跳过失败轨迹或用别的任务补齐。这保留了冻结任务数与任务分布，避免系统故障造成隐性样本替换。

## 4. 已知边界

本实现能够拦截抛出的认证、配额、限流、网络、服务端和空响应异常，但不能仅凭文本可靠识别所有“HTTP 200、上游内部已回退”的语义异常。直接把“转人工”等文本列为黑名单会误伤真实业务场景。

后续应优先利用 LiteLLM/tau2 的原始响应元数据、finish reason 和错误标志，而不是依赖自然语言关键词。若上游完全吞掉错误，需要在更靠近 provider client 的边界增加结构化状态传播。

## 5. 测试

当前专项测试覆盖：

- 认证失败分类与 Key 脱敏；
- 暂时性超时重试后成功；
- 空响应独立记录并中止；
- 最小 API preflight 成功；
- preflight 失败写入系统故障且不泄露 Key；
- runner 在 API preflight 失败时不会执行 runtime/GPU 加载。

本地测试不调用真实 DeepSeek。

## 6. 与多步 SFT 的关系

Fail-fast 先保证采集和评测链可信，多步 SFT 再解决模型能力问题。下一版多步 SFT 数据不能继续使用：

```json
{"user_message": "...", "expected_call": {"name": "..."}}
```

而应保存带监督边界的完整消息序列，例如：

```json
{
  "scenario_id": "...",
  "messages": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "..."},
    {"role": "assistant", "tool_calls": ["..."]},
    {"role": "tool", "content": "..."},
    {"role": "assistant", "tool_calls": ["..."]},
    {"role": "tool", "content": "..."},
    {"role": "assistant", "content": "..."}
  ],
  "training_eligible": true,
  "source_quality": "AUDITED_OR_CORRECTED",
  "tool_result_consumption_required": true
}
```

训练目标必须覆盖“工具返回后的下一次 Assistant 决策”，而不只是第一次工具格式。正式数据仍受人工审计和训练数据 release gate 约束；开发者合成数据只能作为隔离工程实验。
