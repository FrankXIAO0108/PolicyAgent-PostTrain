## 5. 判定

Task 113 同一 prompt 下同时出现有效模型负例和至少一个干净正例，说明 checkpoint 具备可探索行为，任务本身不是“完全不会”或“采样全对”的无梯度任务。

但是 terminal DB reward 把候选 1、2、3 全部记为 `1`，无法区分：

- 正确终态但退款时效陈述错误；
- 正确终态但编造标识、产生工具错误；
- 干净完成。

因此本轮资格结论为：

```text
ELIGIBLE_ONLY_WITH_AUDITED_STAGED_REWARD
```

禁止直接启动 terminal-only GRPO。下一张任务卡应先冻结 Task 113 staged reward，使上述三类 terminal positive 获得可解释的不同分值，再进行短程参数更新和冻结后采样。

### 8.1 对抗性边界

1. v7 证明的是这四条冻结轨迹上的确定性排序，不证明模型经过训练后会改进。
2. claim-check `PASS` 只表示没有触发已配置冲突规则，不表示所有自然语言声明均已验证。
3. 当前退款规则检查 Task 113 用户资料中不存在礼品卡。若其他任务同时存在多种支付方式，必须绑定具体订单的原支付方式，不能复用当前规则。
4. 对错误声明施加上限可能促使模型省略退款说明；冻结后评测仍须检查必要沟通完整性，不能只看 Reward。
5. v7 仍为 `OFFLINE_SHADOW_ONLY`，在单独的在线训练任务卡完成配置、测试和资源审查前不得用于参数更新。
