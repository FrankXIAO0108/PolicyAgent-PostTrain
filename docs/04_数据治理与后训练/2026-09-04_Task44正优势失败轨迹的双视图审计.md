## 2. 关键纠正：两种轨迹不是同一个视图

1. **模型生成视图**：trainer Parquet 保存完整生成 completion，含工具调用、观测和末尾自由文本。
2. **环境可见视图**：raw 的 `messages` 序列化环境 `_messages`。业务工具执行与 `respond_to_user` 更新它；未通过通信工具发送的自由文本不会自动成为用户模拟器看到的消息。

实际 prompt 明确要求：所有面向客户的澄清、确认必须经过 `respond_to_user`；客户停止之后才以简短非工具响应结束。

归档代码依据：

- `src/training/run_retail_agentic_grpo.py:846`：运行提示词。
- `src/rl/retail_agentic_env.py:1525`：raw/evidence 持久化。
- `src/rl/retail_agentic_env.py:1867`：`respond_to_user`；1887–1900 生成模拟用户回复、追加消息并更新停止状态。
- `src/training/rollout_diagnostics.py:824`：EOS 与停止原因分类。
- 上游 `D:/tau2-bench/src/tau2/user/user_simulator.py:183`：`is_stop` 检查用户消息中的 `###STOP###`、`###TRANSFER###`、`###OUT-OF-SCOPE###`，不是自然语言“谢谢/没别的了”，也不是 API 的 finish_reason。

因此必须更正 2026-09-03 的口头结论：

- G35R2 **生成了**后续余额/退款说明，但未通过通信工具送给模拟用户；不能说“没有生成后续回复”。文字仍有 `$34.99 total` 混淆风险，不能据此判完全正确。
- G46R3 **生成了**写后总结，但未发送，故环境评分的写后回复分项仍为 0；不能说模型完全不会生成总结。
- G20R1 **生成了**完整确认请求，但停在普通文本；环境没有收到请求，自然没有用户授权和后续写入。

不把未发送文本直接追加进历史环境对话，不编造后续用户回答，也不追溯改分。当前现象支持“未遵守桥接通信协议”，不等于已证明训练框架有路由 bug。

## 5. 为什么此时不直接加 batch 或改奖励权重

- 49 组都有非零 reward 方差；标准化优势计算已与 trainer 核对。尚无证据把失败主要归因于“没有组内梯度信号”。
- G20R1 与 G20R4 都得 0.20 和正 advantage：环境分项只看到查询证据，无法区分未发送尾段里“正确确认请求”与“错误退款限制”。这比单纯把全部 terminal failure 归零更能说明具体盲点。
- G9R2 应先补准确的格式错误诊断；改变其训练资格/分数需要单独决策，不能偷偷改变门禁。
- 需要确认的后续路线：先保持原评分，补充模型完整输出与环境可见对话的诊断、复现通信协议问题；再决定是针对协议做数据修正/训练，还是改变通信适配。不能把未发送内容当作已送达来“修复”分数。
- 更细的步骤级信用分配仍是独立后续议题，本轮没有实现，也未证明仅靠它可以解决上述问题。
