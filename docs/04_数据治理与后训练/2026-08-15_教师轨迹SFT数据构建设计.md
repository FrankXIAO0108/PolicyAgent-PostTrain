## 4. 修正管道

### 4.1 修正模式

全部 4 条选 `ENVIRONMENT_REPLAY`：拆分并行调用会改变调用顺序与 turn 结构，不属于“仅修改 assistant 文字”。工具结果一律来自 tau2 重放，禁止手写。

### 4.2 修正类别（change_log 草案）

- `tool_call_serialization`：同一 assistant turn 的并行读/写调用拆为独立串行 turn（task 113：4 个 `get_order_details`、2 个 `cancel_pending_order`；task 0：并行商品查询、并行写调用同理）；
- `assistant_text_cleanup`：删除工具调用同轮的过渡文字；
- `pii_masking`（task 0 两条候选）：助手文字暴露内部支付方式 ID `credit_card_9513926`（`1ee2c951` 中间消息 1 处、`e0166c34` 中间消息 3 处 + 终答 1 处），需对**全部助手文字**脱敏；工具调用参数与工具结果中的 ID 属冻结证据，不脱敏。
- 所有 user 消息原文保留（含批量确认句），确认覆盖关系不变。

### 4.3 工具与校验

- 新建 `src/training/correct_tau2_teacher_trajectory.py`：输入证据包 + 机器可读修正计划 → 产出修正消息 → tau2 重放绑定真实结果与终态 → 输出 v0 修正产物（含 replay manifest 与哈希）。
- 校验：`D:\tau2-bench\.venv\Scripts\python.exe -m src.training.correction_validation`（强制：每 assistant turn 恰好一个调用、禁止文字/工具混排、tool 结果匹配前置调用、source/policy 哈希一致）。
- 政策绑定：上游 `D:\tau2-bench\data\tau2\domains\retail\policy.md`（上游提交 `58e5e1ac…`，SHA256 `4313D3FEF8ACF919F555FA17FBCE929CC3ED1CEF2DD8F0D35FF5C8C3364DE176`，6699 字符）。

### 4.4 审批约束

发布需要两条**与作者不同身份**的 `APPROVE`。审阅身份定为两个：

- `user_reviewer_a`：项目所有者（人工审阅）；
- `assistant_reviewer_b`：本机助理扮演的第二审阅身份（经项目所有者指定）。

修正产物由修正管道（`tau2_teacher_correction_pipeline_v1`）作为作者生成，两个审阅身份均与作者不同，可各自独立 `APPROVE`。

**同源偏差记录**：`assistant_reviewer_b` 构建了审计工具并起草了原始复核标签，与作者同源，不是人类意义上的独立审阅。该身份只作为第二道确定性检查，不提升为“独立人类裁决”表述。

## 5. 教师候选级 SFT 决策管道（2026-08-15 已实现）

现有 `sft_decision_builder` 按 task 索引、要求 `ADJUDICATED` policy 标注与质量标注严格配对，是为 20 行 verifier gold 构建的。教师候选是 candidate 级、且本轮没有独立裁决的 policy 标注。两条路径：

- A（已实现）：`src/training/teacher_candidate_decision_builder.py`（+ 7 项单元测试），映射 `CORRECTION_REQUIRED → CORRECTED_POSITIVE`、`HOLDOUT → HOLDOUT`，绑定修正产物哈希、来源哈希、TRAIN/VALIDATION 分配与实体组；双审阅必须全覆盖且标签一致，作者不能审自己产物，实体组跨拆分泄漏 fail-closed；输出状态为 `SECOND_REVIEWED`，不冒充 `ADJUDICATED`；
- B（等待）：等 verifier 政策金标完成独立裁决后复用现有管道。缺点：阻塞教师数据流。

干跑结果（2026-08-15，`_local_private_runs/20260815-tau2-teacher-decisions-v1/`）：6 条已审 → 4 条 `CORRECTED_POSITIVE`（TRAIN）+ 2 条 `HOLDOUT`，`ready=true`。因 task 0 / task 113 各自两条候选共享同一用户与订单实体，当前只能全 TRAIN；VALIDATION 拆分须待 pilot 扩量后按实体组分配，否则必泄漏。candidate 级发布门禁（复核模板 + 发布 manifest + `sft_release` 适配）仍未建，SFT JSONL 保持 0。
