# Agent RL 云端运行手册（AutoDL 单卡 4090）

## 1. 运行顺序

严格分五段运行，不要直接启动 10-step：

```text
环境预检
→ 1 条客户 opening API smoke
→ 1-task / 1-step Agentic GRPO sanity
→ 补齐 44 条 opening
→ 10-step Agentic GRPO
```

训练脚本不会静默回退到 Hugging Face base model，也不会在输入缺失、模型 hash 不符、
tau2 commit 不符或 Git worktree 不干净时开始付费训练。

## 2. 云端目录约定

```text
/root/autodl-tmp/PolicyAgent-PostTrain
/root/autodl-tmp/tau2-bench
/root/autodl-tmp/policyagent-runs/20260802-posttrain-v1/sft_merged
/root/autodl-tmp/policyagent-runs/20260811-retail-agentic-grpo-v1*
```

确认旧 SFT merged checkpoint 仍在原位置。配置绑定的目录哈希必须是：

```text
FCCF589D592CD381BDBF8832264D704120C5EE0C48D60DC33307374C5F0010C1
```

如果目录位置或内容发生变化，先查明原因，不要直接改配置绕过。

## 3. 安装依赖

在云端独立环境执行：

```bash
cd /root/autodl-tmp/PolicyAgent-PostTrain
pip install -r requirements-agentic-rl.txt

cd /root/autodl-tmp/tau2-bench
git fetch --all --tags
git checkout 58e5e1ace69302e6982d27014569c03e0ffccdd2
pip install -e .
```

不要安装 flash-attn，不升级 CUDA。Agentic `environment_factory` 路线要求
Transformers>=5.2；运行器还会检查当前 TRL 的 `GRPOTrainer` 是否真的包含该参数。

## 4. 环境变量

```bash
export POLICYAGENT_PROJECT_ROOT=/root/autodl-tmp/PolicyAgent-PostTrain
export POLICYAGENT_TAU2_ROOT=/root/autodl-tmp/tau2-bench
export POLICYAGENT_USER_MODEL=deepseek/deepseek-chat
export DEEPSEEK_API_KEY='在当前 shell 中设置，不写入文件'
```

密钥不得出现在配置、日志、Git commit 或截图中。

## 5. Step 0：无 API 环境预检

```bash
cd /root/autodl-tmp/PolicyAgent-PostTrain
bash scripts/run_retail_agentic_grpo.sh environment-preflight
```

期望看到：

```text
status = ENVIRONMENT_PREFLIGHT_PASSED
real_retail_tool_result_count = 50
external_api_called = false
```

预检 reward 为 0 是正确现象：它故意只做一次与任务无关的只读调用，验证错误轨迹不会被
奖励。

## 6. Step 1：只生成 1 条客户 opening

```bash
bash scripts/run_retail_agentic_grpo.sh opening-smoke
```

检查：

- `data/retail_agentic_rl_v1/initial_user_messages.jsonl` 只有 1 行；
- manifest 的 `rows=1`；
- opening 是普通客户话术，不包含隐藏 scenario；
- usage 和 cost 被记录；
- 没有 API key 泄漏。

## 7. Step 2：GPU 与 tokenizer 预检

```bash
python -m src.training.run_retail_agentic_grpo \
  --config configs/retail_agentic_grpo_sanity_v1.json \
  --preflight-only
```

必须确认：

- CUDA 为 true，GPU 是 RTX 4090；
- Transformers>=5.2；
- TRL 支持 `environment_factory`；
- tool schema 渲染成功；
- tau2 checkout commit、SFT 模型 hash、opening hash 全部匹配。

## 8. Step 3：1-task / 1-step sanity

先确保 worktree 干净，然后执行：

```bash
bash scripts/run_retail_agentic_grpo.sh train-sanity
```

输出目录默认是：

```text
/root/autodl-tmp/policyagent-runs/20260811-retail-agentic-grpo-v1-sanity
```

至少检查：

- `environment.json`；
- `run_state.json`；
- `raw_rollouts.jsonl`；
- `train_metrics.json`；
- `log_history.json`；
- `agentic_grpo_adapter/`；
- `agentic_grpo_merged/`；
- `run_manifest.json`。

如果失败，先读 `failure_manifest.json`。不要在不理解错误的情况下直接重跑。

## 9. Step 4：补齐 44 条 opening

sanity 通过后继续生成剩余 43 条：

```bash
bash scripts/run_retail_agentic_grpo.sh prepare-openings
```

生成器可断点续跑，但会核对已有行的模型、温度、seed 和 split，绑定不一致时拒绝混用。
最终 manifest 必须为 `rows=44`。

理论 API 调用上限估算：

- opening：44 次；
- 1-step sanity：4 条 rollout，每条最多 8 次客户回复，最多 32 次；
- 10-step：约 40 条 rollout，每条最多 8 次客户回复，最多 320 次；
- 合计硬上限约 396 次用户模拟调用，实际通常显著更少。

实际 token 与费用以 opening manifest 和 raw rollout 中的 usage/cost 为准，不用静态估算替代
证据。

## 10. Step 5：完整 GPU 预检与 10-step

```bash
bash scripts/run_retail_agentic_grpo.sh gpu-preflight
bash scripts/run_retail_agentic_grpo.sh train
```

4090 24GB 对 0.5B LoRA 足够，主要耗时通常来自动态客户 API 往返，而不是模型参数更新。
训练期间可用另一个终端观察：

```bash
nvidia-smi
tail -f /root/autodl-tmp/policyagent-runs/20260811-retail-agentic-grpo-v1/raw_rollouts.jsonl
```

不要把同一个非空 output directory 用于重跑；运行器会拒绝覆盖冻结证据。

## 11. 训练后的必做工作

训练成功不等于模型变好。下一步必须冻结 10 条 `rl_validation` openings，并在一致协议下
比较 SFT 与 Agentic-GRPO。若出现以下任一情况，不扩大训练：

- reward 始终无组内方差；
- tool-call parse 大量失败；
- 重复调用或非预期写操作上升；
- DB success 没提升；
- 高 reward 轨迹经人工检查存在 policy violation；
- 训练只记住 gold action，而不能处理验证任务。

正式 40 条 test 仍保留，不能用来调 reward 权重或 prompt。
