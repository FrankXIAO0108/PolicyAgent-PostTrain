输入沿用 Retail 的 task/actions 和消息对象，不启动环境，不生成工具结果。参数匹配复用 `_action_matches`，所以仍是参考动作覆盖检查，不是对所有合法业务解法的完整判定。

输出包含每次写调用的绑定状态、每项参考写操作对应的成功调用 ID、成功数量与比例。新 `call_index` 是输入中 assistant/user 工具调用的统一索引，不能直接替换旧 action_progress 的 assistant-only 索引。

| 状态 | 本模块的含义 |
|---|---|
| PASS | 调用匹配，且有唯一绑定、晚于调用、明确 error=false、非空的工具返回 |
| FAIL | 未观察到可用的成功匹配：未调用、参数不匹配或工具明确报错等 |
| ERROR | 返回缺失、ID 重复、返回先于调用、错误标志不合法等证据问题 |
| NOT_APPLICABLE | 明确没有参考写操作 |

FAIL 不自动归因到模型：工具报错可能来自环境，缺少写入也可能是轨迹未完成。ERROR 时比例为 null，不能当成零分训练样本。

## 对抗检查

测试覆盖：失败调用不给执行成功计数；错 ID、用户侧返回、提前返回不能冒充正确结果；重复 ID、空内容、缺少错误标志不能默认为成功；失败后新 ID 重试成功可计数；一次调用不能满足两项要求；商品新旧 ID 对重排可匹配但交叉错配不可匹配。

宽、窄条件重叠时采用一对一最大匹配，避免参考动作排列顺序影响覆盖数量。成功调用不能掩盖另一次写入证据缺失，整体仍保留 ERROR。
