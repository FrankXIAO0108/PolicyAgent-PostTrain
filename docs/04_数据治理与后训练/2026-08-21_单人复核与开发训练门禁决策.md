# 单人复核与开发训练门禁决策

日期：2026-08-21  
状态：当前项目治理口径

## 1. 决策

本项目不再把“两位独立业务专家盲审”设为个人项目继续开展开发训练的硬前置条件。
在缺少可获得的电商业务专家时，开发数据采用以下可执行闭环：

```text
冻结原始轨迹与哈希
→ 程序化规则检查和确定性状态回放
→ Codex 提交可追溯预标注
→ 项目所有者逐条复核
→ RAW_GOLD / CORRECTION_REQUIRED / HOLDOUT
→ 修正样本重新校验
→ 实体防泄漏、PII 和发布 manifest 门禁
→ 仅用于开发 SFT / DPO / GRPO 实验
```

这里的“项目所有者复核”不等于业务专家标注，也不等于独立双人 gold。

## 2. 术语和声明边界

| 名称 | 含义 | 允许用途 |
|---|---|---|
| `PROPOSED_BY_CODEX` | Codex 根据 Evidence Pack 给出的预标注 | 等待人工复核，不能直接训练 |
| `HUMAN_ADJUDICATED` | 项目所有者逐条接受或修订后的记录 | 作为单人复核证据；不自动等于专家 gold |
| `RAW_GOLD` | 单人复核后无需修正的高质量开发轨迹 | 通过其他门禁后可进入开发训练 |
| `CORRECTION_REQUIRED` | 主体轨迹可修，但存在过程或回复错误 | 修正并重新校验后才能训练 |
| `HOLDOUT / REJECT` | 含环境冲突、政策歧义或不可安全修复问题 | 不训练，用于诊断或隔离 |

为兼容已有产物，裁决文件继续使用 `HUMAN_ADJUDICATED`；对外必须解释为
“项目所有者单人复核”，不得写成“业务专家金标”或“独立人类 gold”。

## 3. 开发训练的最低放行条件

候选轨迹只有同时满足以下条件，才可进入开发训练：

1. 原始输入、任务、轨迹、模型和配置可追溯，并保存 SHA-256；
2. JSON/schema、工具参数、状态转移和最终数据库回放通过；
3. 项目所有者逐条复核 Evidence Pack；
4. `CORRECTION_REQUIRED` 已生成修正版，并对修正版重新执行校验；
5. benchmark 冲突、Policy 歧义和环境异常样本进入 `HOLDOUT`；
6. TRAIN/VALIDATION 按用户、订单和商品实体防泄漏；
7. 训练与冻结评测分离，不根据评测失败回改同一评测集。

开发 SFT、DPO 或 GRPO 可以在满足上述条件后继续，不再等待不可获得的第二位业务专家。

## 4. 仍然关闭的结论门禁

下列结论仍需要真正独立的人工 gold 或外部业务验证，本决策没有放宽：

- Verifier 相对人工 gold 的正式 Precision、Recall、F1、FP、FN；
- Policy V2.2 的生产准确率或线上可靠性声明；
- “达到业务专家一致性”或“可直接用于生产”的声明；
- 未经冻结对照实验支持的 Retail 业务提升声明。

未经独立 gold 验证的 Policy Verifier 只能作为诊断信号。若将其用于 RL reward，必须
先在本项目单人复核样本上完成逐例 FP/FN 检查，并把结论明确标为开发实验结果，不能写成
生产级 reward model 验证。

## 6. 对抗式审查

放宽双专家门禁会引入四类风险：

1. **确认偏差**：Codex 起草、项目所有者接受，可能共同继承同一错误理解；
2. **规则自证**：用 Verifier 筛数据，再用同一批数据证明 Verifier 正确；
3. **业务覆盖不足**：十条样本不能代表完整电商售后分布；
4. **标签漂移**：不同时间对“必要工具”和“合理停止点”的判断可能变化。

当前缓解方式是保留原始轨迹和哈希、逐条写理由、隔离歧义样本、修正后重新回放、冻结评测，
并禁止报告正式人工 gold 指标。这些措施降低风险，但不能消除缺少业务专家的事实。

## 7. 与旧协议的关系

`2026-07-27_独立政策金标裁决协议.md` 继续作为未来发布正式 Verifier 指标或生产结论时的
高标准协议。本文件仅取代它对**个人项目开发训练**的硬阻塞，不废除其统计与生产结论边界。
