## 3. 规格结构

每份规格包含：`task_id` / `run_name` / `simulation_id` / `review_ids` /
人工裁决绑定（label、severity、disposition、rationale）/ 冻结 source
path+SHA-256 / 冻结 policy path+SHA-256 / `generation_mode =
ENVIRONMENT_REPLAY` / 非空 `change_log` / 有序 `plan`。

计划语义（记录于 manifest `plan_semantics`）：

- `keep`/`remove` 引用冻结事件区间；其余 op 按 `after_event` 锚点顺序插入，
  跳过被移除事件；
- 每个 `tool_call` 后紧跟环境真实生成的工具结果（禁止手编）；
- 用户回复由冻结 `user_simulator`（temperature 0.0，同 seed）重新生成；
  前缀不变的段落与冻结轨迹确定性一致；
- `branch_on_user_reply` 从用户回复提取 allowed reason 填充
  `{user_reason}`；`ask_once_more_then_abort` 兜底（无 reason 则不取消）；
- 总结文案中的金额占位符（`{payment_note}` 等）由重放的真实工具结果填充，
  保证通信与状态一致。
