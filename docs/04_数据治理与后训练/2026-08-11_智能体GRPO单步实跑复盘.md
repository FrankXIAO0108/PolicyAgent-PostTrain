> 日期：2026-08-11  
> 范围：隔离的 Agentic RL 工程验证  
> 结论：端到端链路完成，但奖励零方差，尚未形成有效学习信号。

## 1. 本次运行证明了什么

本次运行在单卡 RTX 4090 上真实走通了以下链路：

```text
冻结的 Retail train 子集任务
-> DeepSeek-V4-Flash 动态顾客 opening
-> Qwen2.5-0.5B SFT 合并模型
-> tau2 Retail 工具环境
-> 4 个候选 rollout
-> 程序化过程奖励
-> TRL GRPO 训练步骤
-> LoRA adapter
-> 合并模型
-> 原始轨迹、指标、哈希和运行清单
```

它证明工程链路可以执行，不证明模型能力得到提升，也不打开正式 Retail
后训练数据门禁。

## 5. 四条 rollout 发生了什么

| 候选 | 工具行为 | 匹配动作 | 结果 |
|---|---|---:|---|
| 1 | 未调用工具 | 0/5 | reward 0 |
| 2 | 未调用工具 | 0/5 | reward 0 |
| 3 | 直接转人工 | 0/5 | 过早放弃，reward 0 |
| 4 | 使用占位符直接执行换货 | 0/5 | 订单不存在、异常写操作，reward 0 |

任务要求先读取订单和商品信息，再完成受约束的换货。当前模型既没有稳定执行读取链，
也没有获取真实 item/payment 标识；这不是奖励函数把正确行为误判为 0，而是候选行为
没有到达第一个可匹配的必要动作。

## 6. 根因分析

### 6.1 冷启动模型不具备 Retail Tool Agent 能力

起始 checkpoint 来自 2026-08-02 的隔离合成后训练工程 smoke，不是经过审核的
Retail 工具轨迹 SFT。它证明过 SFT/DPO/GRPO 脚本链路，却没有学习当前 Retail
工具、参数和业务 SOP。

### 6.2 0.5B 模型的规划和参数落地能力有限

模型能生成结构化工具调用，但出现“直接转人工”和使用 `ITEM_ID1` 等占位符的行为，
说明格式能力强于任务规划和环境 grounding 能力。

### 6.3 当前奖励对完全错误的冷启动候选没有区分度

v1 奖励会区分终态、必要动作进度、沟通、工具错误、重复调用和异常写操作；但本组
四条轨迹都没有匹配任何必要动作，扣分后又统一截断到 0。继续增加训练 step 只会重复
零 advantage，不能依靠 RL 自动跨越这个冷启动区间。

### 6.4 可观测性仍有缺口

原始轨迹完整保存了环境内工具调用和顾客交互，但立即终止且不调用工具的普通文本
completion 没有进入环境消息列表。后续应额外保存模型原始 completion，才能区分
“合理拒绝”“格式失败”和“无工具直接回答”。

## 8. 下一步决策

当前不运行正式 10-step GRPO。先满足以下 reward-variance gate：

1. 仅从 `rl_train` 构建一小批 Retail 工具使用 warm-up 数据，不使用 development
   或 official test。
2. 对 warm-up 轨迹进行程序化检查和人工抽查，确保工具顺序、参数、授权和终态正确。
3. 先做 Retail Tool SFT，使模型至少能稳定完成“读取订单 -> 获取真实 ID -> 再写入”的
   基本链路。
4. 在多个 train 任务上只采样不更新，检查有效工具调用率、必要动作匹配率、reward
   非零率和组内 reward 标准差。
5. 只有当多个 group 出现非零方差，且高分轨迹确实更合规时，才重新启动 GRPO。

建议的最低放行条件：

- tool-call 解析成功率不低于 95%；
- 至少 50% 的诊断 group 出现非零 reward 方差；
- 必要动作匹配率不再全部为 0；
- 高 reward 样本经抽查不存在越权写入或 reward hacking；
- 原始 completion、工具轨迹和 reward breakdown 均可追溯。

## 9. 面试表达

可以准确表述为：

> 我在 RTX 4090 上打通了支持多轮交互的 Retail Agentic GRPO 工程链路，包括动态用户
> 模拟器、工具环境、过程奖励、LoRA 训练、模型合并与全量审计产物。第一次单步实验虽然工程完成，
> 但 4 个候选奖励全部为 0，导致 GRPO advantage 和梯度为 0。我没有盲目扩大 step，而是
> 通过轨迹发现起始模型只有通用后训练经验、没有 Retail Tool SFT，属于典型 RL 冷启动
> 问题。因此后续路线调整为先做严格分割的工具轨迹 warm-up，再以 reward-variance gate
> 决定是否进入正式 GRPO。

本次 4 个候选均未触发后续顾客轮次，因此不能声称已实证多轮交互质量，也不能表述为
“GRPO 已经提升 Retail 成功率”。
