# Qwen3-4B 工具协议 SFT 实验设计

> 状态：代码与数据已完成本地验证，等待云端 preflight 和训练。
> 实验范围：`ISOLATED_TOOL_PROTOCOL_WARMUP`。
> 本实验不开放正式 Retail 数据门禁，也不支持业务效果提升声明。

## 一、为什么先做这一步

Qwen3-4B 的 8-task、32-rollout 诊断中，模型产生了 0 次工具调用。这个现象说明当前
首要问题不是复杂业务推理或 GRPO 更新强度，而是模型尚未稳定掌握 tau2 Retail 的工具
调用协议。此时直接做 GRPO，奖励信号主要由无动作轨迹构成，容易形成无效优化。

因此本阶段只解决一个可证伪的问题：给出客户首轮消息和完整 Retail 工具 schema 后，
模型能否输出结构合法、工具选择正确、必要参数完整的第一步动作。

## 二、数据范围

数据位于 `data/retail_tool_protocol_sft_v1/`：

- 训练集 80 条；
- 独立 holdout 20 条；
- 5 类场景：缺少身份信息的换货、退货、修改请求，以及邮箱认证、姓名加邮编认证；
- 只覆盖 `respond_to_user`、`find_user_id_by_email`、
  `find_user_id_by_name_zip` 三种第一步动作；
- 全部为开发者编写的确定性合成协议样本；
- 不包含冻结 tau2 task 文本，不是人工裁决业务金标。

训练集与 holdout 的场景 ID、消息文本、邮箱、姓名、邮编和订单占位符相互隔离，构建器
会生成文件哈希和泄漏检查结果。

## 三、训练和评测

- 起始模型：`Qwen3-4B-Instruct-2507`，目录哈希固定；
- 方法：4-bit NF4 QLoRA SFT；
- 训练：80 steps，batch size 1，gradient accumulation 4；
- 最大序列长度：8192；
- 评测：同一份冻结 holdout 分别评测 Base 与 merge 后的 SFT 模型；
- 解码：greedy，避免采样噪声干扰协议比较。

核心指标：

1. `valid_tool_call_rate`：能否生成可解析的工具调用 JSON；
2. `malformed_tool_call_rate`：是否尝试调用工具但格式损坏；
3. `tool_match_rate`：首个工具选择是否正确；
4. `argument_match_rate`：必要参数是否完整，认证参数是否精确复制；
5. `ordinary_text_rate`：是否绕过工具直接输出普通文本。

协议 warmup 的目标门槛是合法调用率不低于 90%、工具匹配率不低于 85%、参数匹配率
不低于 80%、普通文本率不高于 10%。该门槛只判断协议学习是否成功。

## 四、运行纪律

先运行：

```bash
bash scripts/run_retail_tool_sft.sh preflight
```

preflight 必须确认模型哈希、数据哈希、上游 tau2 commit、17 个实际工具 schema、CUDA
和渲染后 token 长度。通过后才可运行：

```bash
bash scripts/run_retail_tool_sft.sh train
```

训练输出必须保留 Base/SFT 原始评测行、训练日志、adapter、merge 模型、各目录哈希和
运行 manifest，已有非空运行目录不得覆盖。

## 五、下一道门禁

即使本实验达到目标，也只能说明模型学会了有限的第一步工具协议。下一步仍需进行至少
32 条无更新真实 Agent rollout，验证工具调用率、动作推进率、奖励方差和 reward
shortcut 是否改善。只有这些条件满足，才讨论小步 Agentic GRPO；正式 Retail SFT、
DPO、GRPO 仍受独立人工裁决和数据发布门禁约束。
