# 长轨迹预算与纯采样诊断（S5B）

状态：本地实现待验收；未启动云端采样或参数更新。日期：2026-08-27。

## 1. 为什么新增这条路径

S5 原始证据位于
`_local_private_runs/cloud_grpo_s5_20260827/20260827-staged-reward-write-coverage-tasks43-72-v1/`。
原始 manifest、raw rollout、evidence 和 completion 文件未改写。

当前已核实：

- S5 的 `max_completion_length=1024`；这不是每一次工具调用分别享有的预算。
- 实际使用的 TRL 1.9.0 会把工具结果及模板后缀计入累计 completion 预算。
- 上游循环先执行工具，再检查加入返回后是否超长；超长时回滚的是训练序列中的返回，
  **不是环境中已经发生的写操作**。其 EOS-based clipping 指标不能完整表示该路径。
- 旧 `ROLLOUT_DIAGNOSTIC` 仍调用 `trainer.train()`，只是学习率为零；已有日志含梯度范数。
  因此不能把旧诊断显存等同于纯生成显存。

这些证据说明原能力检查受到长度预算干扰；它们不能逐条证明全部失败都是预算导致。
新路径补充直接观测，不把未知停止原因强行归为模型失败。

## 3. 运行约束

- TRL 必须为 `1.9.0`，`grpo_trainer.py` 必须为 SHA256
  `655D9AD98549290FD32381174BFCA5CAB9F849B839966EDC9A4D3ABE67DD97BC`。
- transformers 必须为 `5.14.1`。不满足就失败，不自动适配。
- 只支持已审阅的单进程、文本、同步工具、transformers 生成路径；不支持 vLLM、
  continuous batching、多模态或异步工具。
- 任务固定 43、72，每组两条，保持原任务 reset 参数、Policy、模型和 Reward。
- 使用新输出目录，显式记录预算覆盖值和组数，不覆盖旧配置。
- 这是隔离的开发诊断，不是生产评测或正式 RL，不释放训练数据。

纯采样复用上游 `_generate_and_score_completions` 的环境构建与 reset，以及 `_generate`
和 `_tool_call_loop`。在 `_generate` 返回后，通过受控内部退出截断评分前向路径。
不会调用 `train()`、loss、optimizer 或 backward；额外禁用参数梯度并检查无残留梯度。
没有复制或修改上游循环。

这一版本绑定适配器依赖私有接口，因此版本或源码哈希变化必须重新审阅。
CPU 合约测试不能代替真实 GPU 模型加载、parser、模板和完整 runtime 验收。

## 4. 长度统计的合同

输入：配置绑定的精确 checkpoint 目录及哈希、checkpoint 血缘绑定的协议桥接数据。
只读取其中 `TRAIN` 行；不使用 VALIDATION 或最终测试集选预算。

输出：每条轨迹的 prompt token、模型 token、观察及模板 token、完整累计长度、
最大单次观察长度，以及总体 min/mean/max/p95。

计数要求：

```text
prompt_tokens + model_tokens + observation_tokens_with_template == total_tokens
```

按 EOS 边界计数；禁止静默截断；发现模板前缀改变或未完整结束的轨迹就停止。
报告会列出 1024/4096/8192/16384 候选预算的覆盖情况。
“完整训练轨迹最大长度再加 25% 余量”仅是工程容量参考，不自动批准预算，也不保证未来轨迹覆盖率。

教师完整轨迹用于估算容量，不证明当前 checkpoint 会完成同一任务。
当前桥接数据没有任务 43/72 的直接示范；这个统计是 TRAIN 分布容量参考，不能冒充两任务的精确所需长度。

## 5. 停止原因与证据

新增 `generation_events.jsonl`，逐事件落盘 group_id、候选 row、模型实际输入和生成 token、
保留的生成 token、工具名/参数、真实工具返回与其 token 后缀、是否触发返回回滚。
同一组两个相同 prompt 按候选索引绑定，不能按文本匹配。

新增 `sampling_groups.jsonl`，记录每组全部候选及其停止原因、观察性 reward 和原始行号：

- `USER_STOP_AND_MODEL_END`：用户结束且模型给出非工具收尾；不是业务正确的充分条件。
- `MODEL_END_BEFORE_USER_STOP`：模型先结束；不是系统故障。
- `TOOL_RESULT_BUDGET_EXCEEDED` / `CONTEXT_LIMIT`：工具返回加入后累计预算/上下文超限。
- `MODEL_GENERATION_LIMIT`：生成达到边界或随后被上游累计预算裁剪。
- `TOOL_ITERATION_LIMIT` / `TOOL_CALL_LIMIT` / `CUSTOMER_TURN_LIMIT`：达到执行上限。
- `PARSE_OR_PROTOCOL_ERROR` / `UNRESOLVED_TOOL_CALL`：未形成可验证的正常模型收尾。
- `USER_API_ERROR` / `OOM`：记录事件，中止整个当前诊断，不被上游转成可学习的普通工具错误。

普通工具异常即使出现过，仍可能被模型恢复；不能仅凭异常历史判传输不完整。
对于超限样本，报告边界事实而不自动判断预算太小还是模型循环浪费。
未知结构或候选绑定异常 fail-closed，不猜测工具调用含义。

所有样本的 `training_eligible=false`；即使业务成功，也未经过数据释放审批。
`trajectory_transport_complete` 只表示没有已检测到的传输/边界异常，不等于高质量或成功。
旧环境 raw/evidence 中的 completion 字段不被重写，新事件与组级证据必须一并消费。
不能直接把纯采样产物当作含 trainer loss/entropy/梯度的训练审计产物。

若已经发生工具写入、随后预算不足：

1. 保留原工具调用、真实返回与 DB 快照；
2. 记录它不在模型后续保留序列中的事实；
3. 不回滚 DB、不重试写操作、不补造模型回复；
4. 不以此样本或不完整组进入训练。后续统计必须报告无效组数，不静默调整分母。

import ast, hashlib, sys, types, urllib.request, uuid

assert hashlib.sha256(source).hexdigest().upper() == TRL_SOURCE_SHA256
cls = next(n for n in ast.parse(source).body if isinstance(n, ast.ClassDef) and n.name == 'GRPOTrainer')
method = next(n for n in cls.body if isinstance(n, ast.FunctionDef) and n.name == '_tool_call_loop')
method.decorator_list = []
module = types.ModuleType('_policyagent_audited_trl_loop')
module.parse_response = lambda *a, **k: {'role': 'assistant', 'content': 'done'}
exec(compile(ast.Module(body=[method], type_ignores=[]), '<verified-loop>', 'exec'), module.__dict__)
module.loop = module._tool_call_loop
sys.modules[module.__name__] = module
raise SystemExit(pytest.main(['tests/test_rollout_diagnostics.py', 'tests/test_rollout_token_budget.py', '-q', '-p', 'no:cacheprovider', '--basetemp=D:/PolicyAgent-PostTrain/tmp/s5b-test-' + uuid.uuid4().hex]))
