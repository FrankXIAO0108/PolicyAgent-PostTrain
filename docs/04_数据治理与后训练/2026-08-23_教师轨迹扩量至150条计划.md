# 2026-08-23 教师轨迹扩量至约 150 条计划

## 1. 决策

当前 SFT 数据集只有 53 条多步轨迹、43 个不同任务。该规模足以证明多步 Tool Agent SFT 工程链路，但不足以把单次指标变化解释为稳定能力提升。

本轮不直接承诺生成 150 条可训练数据，而采用两阶段候选生成：

1. Wave A：61 个可用上游 train 任务，每任务生成 2 个候选，合计 122 个候选；
2. 经过规则审核、行为去重和 owner review 后，再依据真实缺口决定是否执行 Wave B；
3. Wave B 每任务最多补 1 个候选，优先零留存任务、欠覆盖类别和当前 SFT 未覆盖任务。

这里的 150 是目标数据池规模，不是自动放行数量。所有候选仍须经过现有数据质量门禁。

## 4. 时间与 API 成本估计

历史 Layer-1 实测：run manifest 记录 32 个候选从 `2026-08-16T13:28:02Z` 运行到 `14:12:36Z`，墙钟时间约 44.6 分钟；8 份原始 `returned_results.json` 中 32 条轨迹的 `agent_cost + user_cost` 合计约 `$0.0532`。

最初按 Layer-1 候选数线性外推，Wave A 122 个候选：

- 墙钟时间中心估计约 170 分钟；考虑轨迹长度波动，按 2.5～4 小时准备；
- DeepSeek API 成本中心估计约 `$0.20`；考虑长轨迹和失败重试，预算按 `$0.16～$0.30`；
- 该步骤使用远程 API，不需要本地 GPU；优先在本机运行以避免无意义的 4090 租用成本。

2026-08-23 的 4 候选 smoke 实测总 usage 为 263,494 tokens，`agent_cost + user_cost = $0.018241312`。按该 smoke 线性外推，122 个候选约 804 万 tokens、约 `$0.56`。该值明显高于 Layer-1 外推，说明任务长度和缓存命中使小样本成本方差很大。因此正式 Wave A 预算修订为 **`$0.20～$0.70`**；时间按约 45 分钟～4 小时准备。以上仍是估计，正式报告必须以新 run manifest 和逐消息 usage 为准。

## 5. 执行顺序

1. 本地只跑任务 10（已覆盖 handoff）和任务 16（未覆盖 mixed_cancel_return）的独立 smoke，共 4 个候选，验证 API、工具环境、落盘和失败恢复；
2. smoke 通过后执行 Wave A 全量，输出目录与 smoke 分离；
3. 运行 schema、工具错误、状态一致性、Policy、PII 和行为指纹检查；
4. 生成 Evidence Pack，由 Codex 先标注，owner 复核；
5. 统计各类别留存率、零留存任务和重复率，再决定 Wave B；
6. 只有 released 数据集冻结并完成实体组防泄漏拆分后，才进行下一轮 SFT。

## 6. 对抗式审阅

- **风险：把候选数当训练数。** 122 是候选，不是 122 条 GOLD；解决方式是保留 release gate。
- **风险：重复任务只增加文本、不增加能力覆盖。** 61 个任务中 37 个已在 SFT 出现；Wave A 保留双候选用于观察同任务行为稳定性，Wave B 必须按缺口定向补，不允许无条件全跑。
- **风险：历史 53% 留存率样本过小。** 它只来自 32 个候选；因此只用于预算，不作为结果承诺。
- **风险：教师与用户模拟器同源。** 两者均为 DeepSeek，可能产生同源偏差；训练释放仍依赖环境校验和 owner review，最终评测使用封存的 task-unseen 集合。
- **风险：过早使用最终测试。** 扩量、SFT 和超参选择只能使用 train/validation/development；23 个最终任务在模型与数据冻结前保持 `SEALED_NOT_RUN`。
