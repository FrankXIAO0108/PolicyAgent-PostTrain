# tau2 教师轨迹数据 Smoke 设计

## 1. 目标

本阶段不训练模型，也不批量生产 SFT 数据。目标是验证以下最小闭环：

```text
DeepSeek 教师盲生成
→ tau2 Retail 真实工具与数据库执行
→ tau2 确定性离线评测
→ 保守的过程质量分层
→ 人工复核候选
```

这里的“盲生成”是指教师 Agent 只能看到 Retail Policy、工具定义、已经出现的用户消息和真实工具返回。教师在生成时看不到 expected actions、gold database state、evaluation criteria 或隐藏 user scenario。

## 2. 三个 Smoke 任务

三个任务均来自冻结的 `rl_train`，与 `rl_validation`、20 条 development audit 和官方 test 不重叠。

| Task | 类型 | 选择原因 |
|---|---|---|
| 57 | 条件查询 | expected actions 为空，用于防止验收器把“匹配动作数量”误当成唯一质量标准 |
| 113 | 多订单取消 | 检查身份验证、写操作确认、完成度和正确停止 |
| 0 | 双商品换货 | 检查商品变体检索、参数正确性和合并执行一次写操作 |

每个任务生成两条候选，共六条。这个规模只能验证工程链路和暴露失败模式，不能证明 DeepSeek 已具备教师资格。

## 3. 自动分层

自动系统只允许输出三类业务候选标签：

- `AUTO_PASS_CANDIDATE`：没有发现确定性失败，仍需人工复核；
- `REVIEW_REQUIRED`：存在 expected-action 差异、重复调用、未检测到确认等需要语义裁决的信号；
- `REJECTED`：最终数据库错误、工具报错或异常终止等确定性失败；
- `SYSTEM_FAILURE`：轨迹或评测数据缺失。

自动系统永远不输出 `GOLD`，并固定 `sft_release_allowed=false`。

原因是：expected actions 不保证是唯一正确路径；当前 confirmation 和 Policy Verifier 仍属于未通过独立人工金标验证的诊断信号。让这些规则自动发布训练数据会造成自证闭环。

本版额外关闭四个已识别漏洞：

1. Task 57 因缺少可直接验证的动作和沟通断言，固定进入 task-specific semantic review；
2. 用 tau2 replay 重建相关实体的 initial/final state 和字段级 state diff；
3. 对绑定明确订单号的完成态声明执行保守 Claim-State 检查，否定或模糊表达只进入 REVIEW；
4. 使用不改变上游生成逻辑的 audited teacher agent 保存实际出站请求，并扫描结构性 gold 泄漏标记。

第 4 项只能证明“运行时请求中没有出现已定义的结构性 gold 字段”。它不能排除模型预训练见过 tau2，也不能把正常出现在用户对话中的订单号等业务值当作泄漏。因此报告必须使用 `gold_visibility_check_passed`，不得声称绝对盲测。

## 4. 配置与代码

- Smoke 配置：`configs/retail_tau2_teacher_trajectory_smoke_v1.json`
- 生成 Runner：`src/training/run_tau2_teacher_trajectory_smoke.py`
- 候选质量逻辑：`src/training/teacher_trajectory_quality.py`
- 离线审计入口：`src/training/audit_tau2_teacher_trajectories.py`
- 定向测试：`tests/test_teacher_trajectory_quality.py`

## 5. 运行方式

本地仅验证冻结配置，不调用 API：

```powershell
python -m src.training.run_tau2_teacher_trajectory_smoke --validate-only
```

云端正式 smoke：

```bash
cd /root/autodl-tmp/PolicyAgent-PostTrain
export POLICYAGENT_TAU2_ROOT=/root/autodl-tmp/tau2-bench
export PYTHONPATH="$PWD:$POLICYAGENT_TAU2_ROOT/src${PYTHONPATH:+:$PYTHONPATH}"
export DEEPSEEK_API_KEY='在终端中输入，不写入文件'

/root/autodl-tmp/venvs/policyagent/bin/python \
  -m src.training.run_tau2_teacher_trajectory_smoke \
  --output-dir /root/autodl-tmp/policyagent-runs/20260813-tau2-teacher-smoke-v1
```

运行完成后应至少产生：

- `run_manifest.json`：版本、配置、模型和运行状态；
- `private_evaluation/task_*/task_snapshot.json`：隐藏任务和评测定义；
- `private_evaluation/task_*/returned_results.json`：完整 tau2 Results，只用于审核；
- `private_evaluation/teacher_prompt_audit.jsonl`：教师实际出站请求和泄漏扫描；
- `public_candidates/task_*/candidate_trajectories.jsonl`：不含 Task 定义的候选轨迹，仍不可直接训练；
- `candidate_audit.jsonl`：逐候选自动分层；
- `audit_summary.json`：分层汇总与关闭的发布门禁。
- `review_packets/`：相关初始/最终状态、state diff、关键事件和自动检查证据。

Smoke 不创建 `released_training_data/`。后续 SFT builder 必须只接受独立发布流程产生的白名单 manifest，禁止递归扫描整个 run 目录。

## 6. 人工复核重点

自动通过的候选仍需逐条回答：

1. 是否正确理解用户最终意图，而非仅复刻 expected actions；
2. 每个工具调用是否必要，参数是否来自可观察证据；
3. 是否在写操作前完整列出影响范围并得到明确确认；
4. 是否存在重复查询、重复写操作或可以缩短的路径；
5. 工具结果、最终数据库状态和面向用户的陈述是否一致；
6. 是否在任务完成或人工转接后立即停止；
7. 这条轨迹是自主成功、oracle 辅助修正，还是人工修正。

只有人工复核并记录裁决依据后，候选才可能进入后续 `GOLD` 或 `SILVER_CORRECTED` 数据池。

## 7. 下一阶段判定

完成六条 smoke 后，先查看拒绝原因和人工分歧，再决定是否进入 12 任务、每任务四候选的 teacher pilot。不得因为六条中出现成功样本就直接扩展到 44 个任务，更不得据此启动 GRPO。
