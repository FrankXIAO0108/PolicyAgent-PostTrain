## 1. 唯一目标

从与 Terminal 相同的 SFT protocol-bridge checkpoint 重新训练 Staged v6，完成 50 个 optimizer step、200 条训练 rollout，并进行同协议前后采样。不是继续训练 Terminal checkpoint-50，也不是沿用旧 Staged checkpoint-5。

这是单个已用于训练的 Task 44 上的工程实验，不是独立测试集泛化实验。分层 Reward 是否更好是待检验问题，不是前提。

## 3. 奖励：沿用已有 v6，不同时调权重

先求加权分，再施加上限、扣罚、裁剪至 [0,1]：

`S = 0.35×终态 + 0.10×用户结束 + 0.08×身份归属 + 0.12×目标证据 + 0.20×写操作授权 + 0.15×写后沟通`

| 分项 | 代码实际判据，不夸大语义 |
|---|---|
| 终态 0.35 | tau2 环境终态 evaluator 为 1；不要求用户已结束 |
| 用户结束 0.10 | 用户模拟器明确结束；模型自行 EOS 不算 |
| 身份归属 0.08 | 当前实现要求成功查到用户后，再通过 get_user_details 验证订单归属 |
| 目标证据 0.12 | 对指定订单和商品的成功查询覆盖率，并受身份归属门控；不等于模型已理解全部返回值 |
| 写操作授权 0.20 | 必要写调用匹配、绑定真实非错误返回、身份门控及确认参数绑定；PASS=1、REVIEW=0.5、FAIL=0 |
| 写后沟通 0.15 | 必要写调用已验证、必要信息有工具依据并被表达、写返回之后存在 assistant 文本 |

限制：现有“写后沟通”并不证明所有自然语言陈述正确，所需信息也未必在写后的那句文本中重述；不使用 LLM Judge，不宣称完整事实一致性。

上限和扣罚按当前代码顺序执行：

- 没有已验证的必要写操作：扣罚前至多 0.25。
- 完成必要写但身份/确认 FAIL：扣罚前至多 0.15。
- 确认 REVIEW：该分项取 0.5，扣罚前至多 0.75。
- 终局成功但必要沟通不完整：扣罚前至多 0.90。
- 工具错误每次扣 0.03，上限 0.09；相同名称与参数的重复调用每次扣 0.02，上限 0.06。
- 用户交互/工具次数触顶扣 0.10。
- unexpected write 最终上限 0；它是当前 reference-action 匹配的判定，并非完整业务权限证明。
- 仅工具循环次数耗尽时，环境层最终覆盖为 reward=0；截断、超窗、未解析工具调用及系统失败仍 fail-closed，不伪造 0 分进入训练。

**这是分层轨迹评分，最终仍向 GRPO 传入一个标量，不是逐动作 advantage 或独立过程奖励模型。** 旧 nonterminal 权重字段为兼容 scorer 保留，在 v6 最终加权计算中不与上述六项重复相加。

实现依据：`src/evaluation/staged_reward_shadow.py::score_rollout`、`_identity_link`、`_required_write_progress`、`_post_write_response`，以及 `src/rl/retail_agentic_env.py::tiered_terminal_process_reward`、`RetailAgenticEnvironment.get_reward`。

## 4. 本轮离线审查与未解决风险

对刚备份的 Terminal 训练分支 200 条轨迹，使用真实 evidence 和既有确认诊断离线重算 v6，未调用 API：

- 50/50 组 v6 标准差非零；这是离线评分结果，不是新 Staged 训练结果。
- Terminal 成功 112 条的 v6 均值约 0.7933；Terminal 失败 88 条的均值约 0.2098。两类仍重叠，不能以均值证明判定可靠。
- 17 条 Terminal 成功样本被压到 ≤0.15：行 21/26/61/68/70/82/84/85/94/99/116/141/143/151/154/175/194。
- 其中有的来自缺少确认，有的即使确认 PASS 仍低分，例如行 26、82。必须核对身份检查是否只接受一种查询路径，而误罚已有充分归属证据的合法路径。不能将这些 17 条直接当作已证实违规，也不能因有方差就放行。
- 未完成对话但状态正确的轨迹最高可得 0.9，是“状态”和“交互结束”拆分的直接结果；对提前 EOS 的激励差只有 0.1，需要在冻结评测观察，而非预先保证有效。
- 重复扣罚存在封顶，长工具循环仍可能出现；正常再次核验状态也可能被相同参数规则计作重复。

离线结果：`_local_private_runs/20260903-task44-staged50-design/offline_rescore.json`；原始产物：`_local_private_runs/20260903-task44-terminal-grpo-resume40-v1/`。

**上云前剩余的是明确的奖励争议核对，不是再增加算法、模型或数据规模。发现误罚时需另立最小修正并更新版本，不能悄悄改 v6 后沿用旧名称。**

## 5. 执行顺序与预算（等待单独授权）

1. 本地解决上述身份/确认争议，确认可接受的评分语义。当前状态未通过此项。
2. 远程核验 GPU、模型哈希、依赖、修复后的三个运行文件及 scorer 哈希。
3. 从 SFT 预采样一组 n=4，不更新参数；必须无传输/系统失败、有 reward 差异，并包含经轨迹核对的完整正确样本。失败就报告，不自动扩 n 或改权重。
4. 同一 SFT 起点启动全新的 50-step 训练，不把预采样计入 200 条训练样本。checkpoint-10/20/30/40/50；异常即保留证据中止，不自动重试。
5. SFT 与新 Staged checkpoint-50 同协议各 n=4：模型采样 seed=20260904、temperature=0.8、预算8192、相同 Task/opening/user_seed。合计 8 条，仅作开发性同任务比较，不能叫独立实体 holdout。
6. 拉回模型、checkpoint、配置、命令、日志及轨迹；做 SHA256 校验后提醒关云；绘制四张真实训练曲线。

设计预算：4 条预采样 + 200 条训练 + 8 条评测 = 212 条新 rollout。**本文件不构成 API、上传或 GPU 消耗授权。**

## 6. 比较口径

只比较共同 evaluator 的终局成功、DB 状态、提前 EOS、确认诊断和成功/失败条件下的工具数。不得横比 Terminal 与 Staged 的 train/reward 均值。

旧 Terminal 50 步经历长度调整和生成修复，只能作为历史参照；严格 A/B 必须两臂从 SFT、在相同修复后代码和配置下独立运行。新 Staged 与当前 Terminal 参考配置除了 reward 外逐字段一致，但这不使旧历史运行自动成为严格对照。此次不自动安排重跑 Terminal。
