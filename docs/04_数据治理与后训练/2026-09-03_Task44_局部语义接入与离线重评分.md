## LLM与规则的职责

| 内容 | LLM输出 | 规则执行 |
|---|---|---|
| 确认语义 | AFFIRM / DENY / CHANGE / UNCERTAIN，提议和用户回复索引、原文引用 | 检查最近一次确认、是否发生后续修改、是否有明确拒绝 |
| 确认参数 | 用户同意的订单、原商品、新商品、付款方式、退款金额 | 对比写调用；金额与写前价格差、绑定写结果分别核对 |
| 事实声明 | 每个availability / cheapest / refund_amount声明及消息索引、逐字引用 | 用声明发生前的产品结果核对可用性、最低价；退款结合时序核对价格差或已发生退款 |
| 工具、身份、环境终态、安全封顶 | 无权限输出 | 沿用原规则 |
| 最终奖励 | 无权限输出 | 用现有权重合成候选分数 |

提取schema不接受总体quality、reward或PASS/FAIL字段。没有实质声明时`claims=[]`，
不需要为了获得PASS编造引用。消息覆盖列表只是格式检查，**并不能证明声明被完整提取**。

## 评分变化的准确含义

基线为 `task44_evidence_v2` 的hierarchical v6规则。

只允许改变两个槽位：

1. `write_authorization`：局部语义经参数、价格差、实际退款校验后可补足确认；
   现有硬规则FAIL不允许被LLM的AFFIRM覆盖。
2. `post_write_communication`：若某条提取声明被规则证实与事实矛盾，将现有
   沟通分从0.15撤销。不因缺失、UNKNOWN或没有发现错误额外加分。

第二项的离线候选语义扩大为“包括写前解释在内的沟通事实一致性”，不再仅检查
写后是否回复。权重仍为0.15，没有新增惩罚权重；该变化明确作为离线候选保留。

其余环境状态、用户结束、身份、目标证据分量不变。授权FAIL封顶0.15、REVIEW
封顶0.75、无写入封顶、未授权额外写入封顶、工具/重复/长度惩罚、运行时override
均保留。缺失或无效提取回退原规则分数；**回退不是宣称该轨迹安全**。

### 重要案例和限制

- 21/70/94/143/154：局部提取补足上下文授权，规则核对通过。70原有0.15工具及重复
  调用惩罚仍存在，所以不是1.00。
- 85：授权补足后不再受0.75封顶；同时原商品可用性矛盾被提取并证实，撤销0.15
  沟通分，最终0.85。总分增加不等于事实错误被原谅，两个分量需分开阅读。
- 175：提取失败也不能洗掉原来的退款确认错误，仍保持0.15。
- 116/141：非逐字引用导致全条回退；本版本没有用模糊匹配修复引用，也没有局部
  保留一份结构错误输出中的其他字段。
- 194：LLM只提取最便宜商品和退款声明，漏掉“白色、高亮度、USB商品不可用”的
  错误声明。候选分数为1.00暴露出漏检风险，**不能当作完整合规或高质量证明**。

当前实现证明了局部接入可运行、可追溯和规则封顶可保留；尚未证明语义提取完整或
评分更可靠。线上训练保持不变。后续重点是声明覆盖与独立抽查，不是继续堆总体Judge。
