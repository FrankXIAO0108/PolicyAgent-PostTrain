## 7. 训练后决策

1. 先比较两条 v3 运行在同一 22 条 validation 集上的 loss、稳定性和训练成本；
2. 不解封最终 23-task 集，不使用它选择 checkpoint；
3. 使用既有开发评测和残余失败审计验证停止、循环、错误恢复与必要 Tool Use，但必须保持开发口径；
4. 若 116 steps 相对 80 steps 仍明显改善，证据支持继续 SFT；
5. 只有残余问题主要表现为可稳定区分的偏好、禁止行为或长程信用，且过程 Reward 在成功轨迹上不误罚时，才进入 DPO 或 Agentic GRPO；
6. PPO、DPO、GRPO、GSPO 的同 checkpoint 小规模对照属于算法工程附录，不得替代主线的证据分流。

## 8. 对抗式审阅

1. 80 条仍是个人项目级开发数据，不是工业规模；
2. 27 条新增修正轨迹同时改变了任务覆盖与 validation 组成，不能把任何单次变化归因到某一条数据；
3. fixed-budget 与 equal-exposure 只能分离训练预算的一部分影响，仍需多 seed 或多 trial 才能判断稳定性；
4. Owner 审核与助手复核不等于独立业务专家金标；
5. 最终 task-heldout 允许实体重叠，只能支持项目内部新任务迁移结论；
6. 在看到最终 holdout 结果后不得再修改训练、Reward、Verifier 或阈值并重新宣称其为最终结果。
7. 80-step 优于 116-step 的差异来自单一 seed 和一个 validation 集；可以据此选择当前 checkpoint，
   但不能把 1.888% 差异包装成稳定的普遍规律。
8. teacher-forced assistant loss 只说明模型更贴近审核轨迹，不等于真实 Agent rollout 的任务成功率、
   Policy 合规率或 Tool Use 效率已经提升；必须由下一阶段 tau2 开发回归验证。
