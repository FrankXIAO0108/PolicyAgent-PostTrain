# 教师 SFT 配对人工复核批次 1

日期：2026-08-21  
状态：Evidence Pack 与 Codex 预标注已完成，等待人工逐条裁决

## 1. 目的

在现有 30-task Base/SFT 冻结开发对比上，建立“Codex 预标注 + 用户人工裁决”的可追溯流程，用于标定以下过程维度：

- 最终用户意图；
- 必要、允许和不合理工具调用；
- 合理调用区间；
- 正确停止点；
- 状态一致性与意图完成度；
- 最终回复正确性；
- Policy 安全；
- benchmark 与实际动态对话是否冲突。

Codex 预标注身份为 `PROPOSED_BY_CODEX`，不是人工 Gold。只有用户逐条确认后才能升级为 `HUMAN_ADJUDICATED`。

## 5. 首轮关键发现

1. task 36 的 45 次调用不能只按数量判错。实际最终取消符合动态用户意图，但 35 次 `get_item_details` 在 `get_product_details` 已返回 variants 与价格后属于可删除查询；同时静态 gold 仍要求修改商品，存在 benchmark/user-simulator 冲突。
2. task 38、90 的 reward=0 均只由取消理由与静态 gold 冲突导致；实际 Agent 使用了动态对话中用户最后明确指定的理由。
3. task 40 的 reward=1 与 DB Match 没有发现最终回复中的 Mastercard/Visa 实体矛盾，证明 outcome reward 存在回复事实一致性盲点。
4. task 72 的最终状态与 gold 完全一致，但 V2.2 报 one-shot order mutation；benchmark 本身要求 item 与 address 两次写入，因此该 finding 是待人工确认的 verifier FP。
5. `state_consistent` 与 `intent_fulfilled` 已拆分：数据库可以内部一致，但写操作参数仍可能未经用户授权。

## 6. 裁决纪律

人工每条选择：

- `ACCEPT`：接受预标注关键字段和质量标签；
- `CORRECTION_REQUIRED`：指出需要更正的字段；
- `REJECT`：预标注整体逻辑不可用。

裁决必须带理由。未裁决标签不能计入 Verifier Precision/Recall/F1，也不能释放训练数据。
