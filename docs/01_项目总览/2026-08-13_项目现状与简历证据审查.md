## 三、已确认结果

1. 冻结 20-task Retail 开发基线为 16/20 业务成功、0/20 系统失败；不是官方榜单。
2. Base Qwen3-4B 的 8-task、32-rollout 无更新诊断中，工具调用为 0/32，平均必要动作
   recall 为 0，`ready_to_consider_optimization=false`。
3. 隔离 Tool SFT 使用 80 条合成训练数据和 20 条同分布 holdout，合法工具调用率、
   工具选择率和参数匹配率均从 0% 提升到 100%。该结果只证明有限第一步协议学习。
4. 正式 SFT release 为 `ready=false`、released=0；正式 SFT、DPO、GRPO 门禁均关闭。
5. 2026-08-13 本机全量测试为 114 passed、8 failed、9 subtests passed。8 项失败来自
   本机 tau2 依赖导入问题；不能写成“全部测试通过”。

## 四、简历中的证据冲突

当前简历第一项目存在以下不可证实表述：

1. “完成 Base/SFT/GRPO 对比实验”：正式 Retail 证据不成立。只能拆分为“完成隔离
   SFT-DPO-GRPO 工程 smoke”和“完成 Qwen3-4B Tool SFT 协议 warmup”。
2. “业务成功率由 79.06% 提升至 90.34%”：仓库没有对应冻结任务、分母、manifest
   或原始结果。20-task 实验不可能自然产生这两个百分比，必须删除。
3. “Policy 违规任务数由 4/20 降至 1/20”：没有可比较的 Base/GRPO 冻结产物，必须删除。
4. “完成 GRPO 后训练实验”：只对隔离 Qwen2.5-0.5B smoke 成立，不对正式 Retail 或
   Qwen3-4B Agentic RL 成立。

## 六、下一步验收条件

云端恢复后，读取而不是重跑上次启动的 Tool-SFT 后 32-rollout 目录。只有同时满足：

1. observed rollouts = 32，且 8 个任务各 4 条；
2. 工具调用率显著高于 Base 的 0/32；
3. 必要动作 recall 出现非零且有组内方差；
4. reward 方差来自真实动作推进，而非 environment-state shortcut；
5. 无大面积工具格式错误、循环澄清或错误写操作；

才进入小步 GRPO 设计。否则应扩展多轮纠正 SFT 数据或修正环境/奖励，不扩大 RL steps。

## 七、对抗式审阅

- 20 条同分布 holdout 的 100% 很可能高估泛化，不能替代真实多轮任务。
- 20-task baseline 与 Qwen3-4B Tool SFT 使用的模型、数据和目标不同，不能直接相减。
- Verifier 的开发集一致性不是独立人工 gold 的 precision/recall。
- “拥有 GRPO runner”不等于“GRPO 有效”；优化前必须先证明 rollout 和 reward 可学习。
- 目录更简洁不会自动提高项目质量，证据闭环和可复现性优先于表面结构。
